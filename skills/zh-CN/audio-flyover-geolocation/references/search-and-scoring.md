## 1. 网格与轨迹重采样

- 隐式全球网格（`Grid(spacing)`，默认 200 m），节点 id 稳定，只实例化航迹走廊内的节点。
- ADS-B 航迹按 1 s 重采样：经纬度 PCHIP、 高度线性；速度用报文 gs/track/vrate 合成 ENU → ECEF。
  有空白（> 45 s）的地方切段，不跨段插值。
- 观测点 = 网格节点经纬度 + DEM 高程 + 麦克风高度（默认 2 m），全部在 ECEF 里算 3D 斜距。

## 2. 漏斗 A：事件 1 走廊

1. 只取类别在 `--event-classes`（默认 prop,rotor,unknown）、地速在 [v_min−3, v_max+3] m/s 的轨迹样本；
   已知录音时钟时再限制到 rec_start + t_rec ± (时钟容差 + t_tol + d_max/c + 60 s)。
2. 对这些样本生成半宽 d_max 的走廊节点（`corridor_nodes`）。
3. 对每个节点求各航班的 CPA（`cpa_events`：稀疏距离矩阵 → 局部极小 → R² 抛物线插值求亚秒 tCPA），
   并计算接收时刻 t_rx = tCPA + d/c（"延迟的 CPA"，正是观测曲线 f = f0 的时刻）。
4. 保留：CPA 不在航迹端点（`edge`）、d ∈ [d_min, d_max]、gs ∈ [v_min, v_max]、
   **k = gs²/d ∈ [k_min, k_max]**，已知时钟时 |t_rx − (rec_start + t_rec)| ≤ 容差 + t_tol。

## 3. 漏斗 B：事件间偏移（两事件）

- ΔT = t_rec2 − t_rec1（录音内两条曲线 f = f0 时刻之差，只依赖录音本身，精确到 ~1 s）。
- 在 A 留下的节点上对事件 2 重复 CPA 匹配，再按节点配对：|(t_rx2 − t_rx1) − ΔT| ≤ tol，
  tol 默认 √(t_tol1² + t_tol2²)，可用 `--offset-tol` 指定。
- `--distinct-aircraft` 禁止两事件是同一架飞机（默认允许：飞机绕场两圈是常见情况）。
- 这一步把"绝对时间未知"变成"相对时间已知"——视频里 920 s 的偏移就是在这里起作用。

## 4. 漏斗 C：静默

- 只有给出 `--rec-duration`（录音总长，秒）时才启用静默过滤。
- 安静区间 = 默认整段录音减去各事件 ±guard（`--guard` 25 s）外加曲线半宽；或 `--quiet "a-b,c-d"` 指定。
- 静默检查对**所有**航班生效（包括 bbox 外的），因为它们仍可能从节点附近经过。
- 对每个候选（节点 + 时间对齐），若有任何 prop/rotor/unknown/jet 航班在安静区间内以小于 `--d-quiet`
  的斜距经过（默认 prop 3000、rotor 2500、unknown 3000、jet 2500 m），候选被淘汰。
- 风险：录音里其实有较弱的飞越没被检测到 → 真值被误杀。说话多、风大时只给确信安静的区间，或调小 d_quiet。

## 5. 打分

对每个候选 (节点, 航班1, [航班2])：
1. `CurveModel.curve`：取航班在 CPA ± (half_window+20) s 的重采样轨迹，按发射时刻精确算 (t_rx, f/f0)。
2. 以事件 1 的模型 t_rx(CPA) 与观测 t_rec1 对齐得到 off0（录音 0 秒对应的 UTC），在 δ ∈ [−delta_max, +delta_max]
   （默认 ±4 s，粗 1 s / 细 0.25 s）上搜索，**两事件共用 δ**（`--lock joint`；`e1` 只按事件 1 选 δ）。
3. 每个事件的 f0 在 1 ± f_rel（默认 ±0.6 %，粗 9 档 / 细 25 档）上独立缩放。
4. 得分 = 沿模型曲线（及 `--harmonics` 倍数）对白化频谱采样的平均强度（裁剪到 0–30 dB）；
   `--trace-mode` 改为与追踪点的高斯距离（极弱曲线时用）。
5. 已知时钟（`--rec-start`）时，超出 ±`--rec-start-tol` 的 δ 被禁止。

为什么要锁定：每个事件单独对齐时间时，错误位置也能把各自曲线"平移"到最佳，得分区分度消失；
共用 δ 保留了"两事件之间的纯物理时间差"这一最强约束。

## 6. 精化、假设、模糊性

- 粗打分后，每个航班对保留至多 `nodes_per_pair`=4 个相距 > 400 m 的节点（镜像两侧都要留）；
  取最佳的 `--top-pairs`（40）个航班对。
- 每个保留节点做 3×3 收缩爬山：步长 `--sub-m`（100 m）→ 50 → 25 m，直到中心最优。
- 每个航班对输出至多 3 个相距 > 500 m 的假设，全体按总分排序。
- `ambiguity`：得分 ≥ `--ambiguity-frac`（0.9）× 最佳、且相距 ≥ 500 m 的其他假设 → `ambiguous_alternatives`。
- `coarse_plateau`：最佳航班对的粗得分 ≥ 0.9×最大的所有节点，主轴长度/宽度/方位。
  单事件无时钟时这就是沿航迹的条带（≈ 2·v·Δt），镜像存在时宽度会跨过航迹。
- `geometry`：两事件航迹在 CPA 处的方位与交叉角；< 25° 给出警告（沿航迹方向退化）。
- 热图：最佳点周围 `--heat-radius`（1500 m）、`--heat-step`（30 m）的细打分，0.9 区域面积与最大半径即误差。

## 7. 输出字段解读

| 字段 | 判读 |
|---|---|
| `best.total` | 绝对值无意义，只用于比较 |
| `margin_vs_2nd` | (第1−第2)/第1；> 0.15 强，0.05–0.15 中，< 0.05 弱 |
| `robust_z` | 第 1 名相对全体假设的稳健 z；> 5 才算显著 |
| `ambiguous_alternatives` | 非空 → 必须在报告中列出并尝试用视觉/地形排除 |
| `coarse_plateau.length_m` | 单事件：> 600 m → 报条带；与 2·v·时钟容差比较可判断是否为时钟退化。两事件时粗打分区分度低，以热图与 `geometry` 为准 |
| `region_max_radius_m` | 报告的误差半径（0.9 区域） |
| `best.rec_start_utc` / `rec_start_iso` | 推断的录音起始 UTC，可与元数据交叉验证 |
| `best.flight1/flight2` | hex / 注册号 / 机型 / 类别 |
| `funnel`（search 的 stats） | 每一级剩余数量；某级骤降到 0 → 看那一级的窗口 |

## 8. 调参与性能

- 速度：200 m 网格、50×50 km、4 h 数据、70 架次 → 合成测试全流程约 30–45 s（单核 Python）。
  全国搜索需要按区域分块（`max_nodes` 300 万节点上限）或先用已知时钟收窄时间窗。
- 漏斗为空时依次放宽：`--c-uncert 0.06` → `fit --k-margin 0.12 --v-margin 0.3` → `--event-classes prop,rotor,unknown,jet`
  → 检查 `--start/--end`、QNH/高度基准 → 检查 ADS-B 覆盖。
- 候选过多（> 10 万）：缩小 bbox、给出时钟、或加第二事件。
- 不要为了"出结果"而收紧到真值可能被排除的程度；漏斗宁宽，打分决定。
