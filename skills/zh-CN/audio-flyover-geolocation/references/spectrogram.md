# 频谱分析与曲线追踪

## 1. 参数选择

| 参数 | 默认 | 说明 |
|---|---|---|
| `--fs` | 4000 | 重采样率；音调在 20–600 Hz，4 kHz 足够且快 |
| `--win` | 1.0 s | 频率分辨率 ≈ 1/win。近距离陡峭段（斜率 > 3 Hz/s）用 0.5–1 s；远、弱、平缓曲线用 2–4 s |
| `--hop` | 0.2 s | 帧移；相邻帧相关，拟合协方差按 √(win/hop) 放大 |
| `--fmin/--fmax` | 20/600 Hz | 直升机主旋翼需要 `--fmin 8` 且更长窗口 |
| `--bg` | 120 s | 背景中值窗口（白化） |

斜率与窗口的折中：窗口内频率变化 Δf = |slope|·win 应 ≲ 1/win，即 win ≲ 1/√|slope|。
例：CPA 斜率 2 Hz/s → win ≲ 0.7 s。

## 2. 白化与门控

- **白化**：每个频点除以滑动中值背景（`--bg`），再做每帧平坦化 → 窄带音调突出、宽带噪声（风、交通、喷气机）被压平。
- **瞬态门控**（`gate_transients`）：某帧中"占用"的频点比例异常高（说话、敲击、风噗）→ 该帧标为 gated，
  不参与检测、追踪输出和拟合。频谱图中这些帧显示为黑色竖条。说话多的视频会有大量门控帧——曲线只要
  在门控间隙里连续可见就够用。

## 3. 检测（`detect`）

- 滑动 60 s 窗口（`--window`、`--step`；最后一个窗口与录音末尾对齐，尾部不会漏检）内做单调下降路径的
  Viterbi 搜索。
- 默认跟踪最亮的单条谱线，无论它是第几次谐波（`--harmonics 1`）。同一频带内所有候选共用一个谐波数，即
  满足 K × fmax 不超过频谱上限的最大 K，所以 40–400 Hz 在 600 Hz 频谱下本来就只能叠加 1 个。曾尝试按候选
  分别计数，但谐波数不同的行噪声离散度不同，检测和自测追踪都变差，已放弃。`boxes.diag.json` 和 `trace`
  会报告实际使用的谐波数；在窄的 `trace` 框里叠加谐波才有收益。
- 每个窗口的路径平均强度与基线比较（`boxes.diag.json` 注明用的是哪种）：
  - **relative**（常规情况）：录音自身各窗口的中位数，需超出 `--thr` dB（默认 0.8）且超出 3.5 倍稳健
    标准差。需要至少 6 个可用窗口，且其中大部分是背景。
  - **noise-model**（短于约 2 分钟的片段，或整段录音几乎都有音调）：用合成高斯噪声、以相同窗口长度跑同一
    流程得到的水平，需超出 `--null-db`（默认 0.8）。白化使该水平与噪声的响度和频谱色彩无关；它与六个自测
    录音的背景窗口相差不超过 ±0.06 dB。在 73 段合成纯噪声片段（12–300 s，含电网嗡声和人声）中没有误报，
    1.5 km 内的飞越超出 1.5–12 dB。真实的风噪、交通噪声不在该测试范围内。
- 命中的窗口串成组。窗口相互重叠，一个组可能横跨两次分开的飞越，所以每组的脊线会再拆分：
  - 失去支撑（5 s 平均低于噪声模型同类值的第 99.5 百分位）且未门控音频超过 10 s 处；
  - 转折点处，即脊线再次上升超过 max(3 Hz, 3 %) 的地方。平缓的接近段和远离段归属各自的飞越。

  只有一段的组保持旧版本基于窗口的框（6 个自测结果不变）。持续 ≥ `--min-dur` 的段成为事件；更短的列在
  `short_hits` 中。
- 趋势：`drop_pct` 比较事件中有支撑脊线点的前 20 % 与后 20 % 的中位数。
  - ≥ 1 % → `descending`。
  - ≤ −1 % → `rising`：不返回，列在 `boxes.diag.json` 的 `rejected` 中。直线飞越的频率总是下降，上升音调是
    测试信号、发动机试车或转弯中的声源。强音调会遮住其下的内容，所以会屏蔽它的脊线、在同一段内再搜一次：
    找到的下降脊线成为事件（带 `note`）或 `short_hits` 条目，该音调也会带上警告。
  - 其余 → `flat`：保留，但要用 `plot` 核对。
- 事件带 `warnings`：脊线再次上升超过容差，或下降超过 45 %（单次飞越下降 2v/(c+v)，75 m/s 时为 36 %），
  多半连接了两架飞机或两条谐波。
- 合成录音实测：
  - 相隔 90–180 s 的两次飞越在 12 例中全部拆成两个事件（v1.1.0：12 例中 4 例，且只在相隔 180 s 时）。
  - 相隔 40–60 s 且同时可闻的两次飞越常仍为一个框，但这些框都带有警告。
  - 单次飞越（150 m–2 km，144 段）和 72 段纯噪声片段的检测结果与 v1.1.0 相同，没有警告，也没有被搁置的脊线。
- `boxes.diag.json` 中的 `status`：`ok` = 结果为空即表示没有本检测器能看到的飞越；`limited` = 用了噪声
  模型，或大部分帧被门控；`insufficient` = 按当前设置无法完成检测（片段短于 `--min-dur`，或几乎全被门控），
  此时结果为空说明不了任何问题。
- 输出按 `score_z`（相对强度的稳健 z 分数）排序更有意义。**检测只是建议**：务必用 `plot` 看图确认，自己调整框。

## 4. 追踪（`trace`）

两遍：
1. 框内谐波叠加 → Viterbi 单调路径（`--penalty` 惩罚斜率变化）→ 与**时间打乱的零假设路径**比较显著性
   （同样的最大值选择偏差，但没有真实连续性），取第 99 百分位为阈值 → 只保留最强的连续段。
2. 用该段做线性拟合；若物理上合理（5 < v < 0.6c，30 < d < 20000 m），沿模型曲线建立走廊重新追踪
   整条曲线（阈值放宽到零假设第 90 百分位），得到两侧尾部。

### 诊断

| 图上看到 | 含义 | 处理 |
|---|---|---|
| 绿点从一条谐波跳到另一条 | 框太宽、谐波强度交替 | 把框收窄到一条谐波（fmin/fmax 夹住） |
| 绿点在曲线前后漂进噪声 | 尾部太弱 | 正常；fit 有稳健损失。若影响拟合用 `fit --tmin/--tmax` 只拟合干净部分 |
| 只有 CPA 附近一小段 | 渐近线不可见 | v、d 单独不准，但 k = v²/d 仍可靠——搜索窗口已按此设计 |
| 曲线中途"台阶" | 两架飞机重叠，或功率变化 | 用 `--anchors` 分开追踪；必要时只用一侧 |
| 上升的曲线 | 转弯朝向你 / 直升机机动 | `detect` 把它列在 `rejected` 中；需要时用 `--no-monotone` 追踪；通常不适合作为主事件 |

### 手动锚点

`--anchors "200:255,230:210,250:186"`：给出几处 (录音秒, Hz)。追踪限制在锚点插值曲线 ±`--corridor` Hz 内。
曲线很弱时这是最可靠的办法——先 `plot` 放大，读出 3–5 个点。

## 5. 谐波识别

- 同一事件会出现 f0, 2f0, 3f0… 的一组平行（比例相同）曲线。检查：各曲线在同一时刻的频率比应为整数比。
- 哪条最强取决于机型与距离，选最干净的那条追踪即可；`score --harmonics 1,2` 会同时用到所追踪线的 1、2 倍。
- 50/60 Hz 电源哼声及其谐波是**水平**线（可能有 ENF 微小抖动），不要误追。ENF 本身也可用于时间取证，但不在本 skill 范围。

## 6. 读图要点（给 Claude）

用 Read 打开 PNG 时关注：曲线是否平滑单调、两侧是否有平台（渐近线）、绿点是否落在亮线上、
青色拟合线是否在 CPA 段与两侧都贴合。看不清就 `plot` 放大到 ±60 s、±40 Hz 再看。
